# StudyBuddy AI

A smart flashcard and quiz study app for IT students, built for CP3406 Assessment 3.
Covers Java, Python, SQL, Networking, and Cyber Security topics with spaced-repetition
flashcards and API-driven quizzes.

## Core Features

| Feature | Implementation |
|---|---|
| Landing Page | `HomeScreen` — streak, flashcards studied, quizzes completed, average score, quick-start actions |
| Activity Screen | `CardsScreen` (topic-filtered flashcards, spaced repetition) and `QuizScreen` (topic selection → play → results/review) |
| Settings Screen | `SettingsScreen` — dark mode, difficulty, question count, daily goal, high-contrast |
| Statistics Screen | `StatisticsScreen` — totals, highest/average score, streak, score history chart, average-by-topic chart |
| Internet Connectivity | Retrofit + Moshi against **Open Trivia DB** (quiz questions) and **Free Dictionary API** (auto-generated vocabulary flashcards) |
| Database | Room — `FlashcardEntity`, `QuizResultEntity`, `UserStatsEntity` |
| Architecture | ViewModel + Repository pattern, Hilt for dependency injection |
| Navigation | Navigation-Compose with a persistent bottom nav bar, typed arguments (`topic`) |
| Testing | JUnit model-logic tests (`src/test`) + Compose UI tests (`src/androidTest`) |

## How It Works

**Data flow, end to end:**

1. **UI layer** (Composable screens) observes `StateFlow`s exposed by their **ViewModels** — nothing on screen is ever fetched directly by a Composable.
2. **ViewModels** call into **Repositories** (`FlashcardRepository`, `QuizRepository`, `StatsRepository`), never touching Room or Retrofit directly. This keeps the ViewModel focused purely on UI state, and means the data source (local vs. remote) can change without the ViewModel knowing.
3. **Repositories** decide where data comes from:
    - Flashcards and stats are read/written through **Room DAOs** and exposed as `Flow`, so any change to the database automatically re-emits new UI state — no manual refresh logic needed.
    - Quiz questions are fetched live from the **Open Trivia DB** API via Retrofit; a "New Card" can also be auto-generated by looking up a word in the **Free Dictionary API**.
4. **Hilt** wires all of this together: DAOs, Retrofit services, and repositories are all provided as singletons via `di/AppModule.kt`, so any ViewModel can request what it needs via constructor injection.
5. **Settings** (dark mode, quiz difficulty, question count, daily goal) are stored in **DataStore**, read reactively wherever needed — including in `MainActivity`, which reads the dark-mode flag to theme the entire app.

**A concrete example — taking a quiz:**

1. User taps a topic on the Quiz tab → navigates to `quiz_play/{topic}`.
2. `QuizViewModel.loadQuiz()` reads the current difficulty/question-count from `UserPreferences`, then calls `QuizRepository.fetchQuestions()`, which hits Open Trivia DB via Retrofit.
3. Each answered question is tracked in `QuizUiState`; on the final question, the score is saved via `QuizRepository.saveResult()` (writes to Room) and `StatsRepository.recordStudySession()` updates the streak.
4. The Statistics screen picks up the new result automatically, since it's observing the same Room table as a `Flow` — no explicit "reload" call needed.

**Offline / error handling:** network calls are wrapped in try/catch; a failed fetch (no connection, API downtime, parsing error) sets an error message in `QuizUiState` instead of crashing, and the UI shows a Retry button.

## Ethical Design Notes (informed by Assessment 2)

- **No PII collected.** All data (flashcards, scores, streaks) is stored locally in Room;
  nothing is transmitted to a server except read-only lookups to the trivia/dictionary APIs.
- **Accessibility.** A high-contrast setting and content descriptions on flashcards support
  users relying on screen readers or with low vision.
- **No dark patterns.** Streak state is shown neutrally ("Streak: 4 days") rather than using
  loss-framed language designed to manufacture anxiety about breaking a streak.

## Project Structure

```
app/src/main/java/com/example/studybuddy/
├── data/
│   ├── local/            Room entities, DAOs, database, sample data seeding
│   ├── remote/           Retrofit services + DTOs

│   └── UserPreferences.kt   DataStore-backed settings
├── di/                   Hilt modules
├── navigation/           NavHost, bottom nav bar, Screen routes
└── ui/
    ├── home/             Landing dashboard
    ├── cards/            Flashcard browsing + spaced repetition
    ├── quiz/             Topic selection, quiz play, results/review
    ├── settings/
    ├── statistics/       Stats + custom charts
    ├── common/           Shared topic styling (colors/icons)
    └── theme/
```

## Running the Project

1. Open in Android Studio (Koala or later recommended).
2. Let Gradle sync — all dependencies resolve from Google/Maven Central, no manual setup needed.
3. Run on an emulator or device with API 26+.

## Testing

- Model/logic tests: `./gradlew test`
- Compose UI tests: `./gradlew connectedAndroidTest` (requires a connected device/emulator)

## APIs Used

- [Open Trivia DB](https://opentdb.com/api_config.php) — quiz questions (Computer Science category, `id=18`)
- [Free Dictionary API](https://dictionaryapi.dev) — definitions for auto-generated vocabulary flashcards
